# 可视化检查标定结果

[English](calibration_visualization.md) · [标定流程](calibration.zh-CN.md) · [README](../README.zh-CN.md)

采集、求解和应用标定仍通过 CLI 完成。`calibration-report` 命令将已保存的结果转换为离线可视化报告，供应用标定前检查。它在不存在或为空的输出目录中写入 `index.html`、`metrics.json` 和 PNG 图。直接在浏览器中打开 HTML 即可；绘图使用 Matplotlib 的非交互式 Agg 后端，无需显示服务器、ROS 或操作服务。

报告读取已有文件，不连接机器人、不移动关节、不修改配置、不将标定标记为已验证，也不启用执行。完成现有 CLI 应用步骤后，前端继续读取已标定配置。

## 检查相机内参

按照[标定流程](calibration.zh-CN.md)拟合原始、未去畸变的棋盘格图像后，在仓库根目录运行：

```bash
.venv/bin/tron2-deploy calibration-report \
  --intrinsics calibration_data/intrinsics.json \
  --images 'calibration_data/intrinsics/view-*/color.png' \
  --output output/intrinsics-review

xdg-open output/intrinsics-review/index.html
```

如果内参 JSON 记录的图像路径仍可解析，可以省略 `--images`。移动或恢复图像数据后，使用带引号的显式通配路径。相机分辨率、棋盘格内角点数量和方格尺寸必须与拟合时一致；报告从内参结果中读取标定板几何参数。应提供原始图像，不要使用已经由该标定结果去畸变的图像。

| 图示 | 检查内容 | 能说明什么 |
| --- | --- | --- |
| 逐图叠加检测角点与重投影点 | 角点落在实际交点处；残差没有明显的随位置变化的规律 | 模型能否解释该视角中检测到的角点 |
| 原始与去畸变图像对比 | 棋盘边缘是否笔直，整个画面及边缘的几何关系是否合理 | 对畸变校正效果的直观检查 |
| 图像覆盖范围 | 视角是否覆盖不同区域，而非集中在中心 | 图像哪些区域实际贡献了测量数据 |
| 逐视角重投影误差，单位为像素 | 结合求解器总体 RMS 检查异常值及视角间差异 | 哪些视角需要进一步检查 |

报告使用所提供的内参估计每幅显示图像的标定板位姿。参与拟合的图像上的重投影误差属于**样本内诊断**，不是独立精度测量。较小的 RMS 不能证明相机到基座对齐正确，也不能证明 RGB-D 深度准确。角点检测不佳、视角过于重复或方格尺寸错误，都可能导致结果不可靠，即使图看起来很整齐。必要时重新采集或修正输入、重新拟合，并在新的目录中生成报告。

运行 `apply-intrinsics` 前先检查图像；该命令仍是[标定流程](calibration.zh-CN.md)中的显式配置更新步骤。

## 检查手眼几何与独立验证点

使用同一侧的 eye-to-hand 求解结果及对应样本集。独立验证使用 NPZ 文件，其中 `points_camera` 与 `points_base` 数组一一对应，单位为米，至少包含三个不共线的点。基座系坐标必须来自独立测量，不能由待验证的变换生成。文件准备方法见[标定流程](calibration.zh-CN.md)。

```bash
.venv/bin/tron2-deploy calibration-report \
  --handeye calibration_data/handeye-left.json \
  --samples 'calibration_data/handeye-left/*.json' \
  --validation-points calibration_data/heldout_points.npz \
  --max-error-m 0.005 \
  --output output/handeye-review

xdg-open output/handeye-review/index.html
```

`0.005` 表示允许最大点误差为 5 mm。评估结果前，应依据部署的实测误差预算确定阈值。这个示例不是通用验收标准。比较使用最大点误差，因此平均误差较小也不能掩盖某个点超标。

| 图示 | 检查内容 | 判读方式 |
| --- | --- | --- |
| 采样腕部位姿及姿态覆盖 | 平移覆盖范围与旋转方向是否丰富 | 重复近似相同的姿态不能提供足够的几何多样性 |
| 标定板在腕部坐标系中的一致性 | 各样本的平移残差，单位 mm；旋转残差，单位度 | 刚性安装的标定板相对腕部应保持一致位姿 |
| 基座系中的预测点、参考点、坐标系及残差向量 | 相机点变换后是否与独立测得的参考点重合 | 对齐误差的方向与位置 |
| 逐点误差柱状图及阈值 | 每个点均满足阈值，并排查异常值 | 最大误差不超过阈值时，独立验证才通过 |

对于每个样本，报告重建标定板在腕部坐标系中的位姿：

```text
T_wrist_board = inverse(T_base_wrist) @ T_base_camera @ T_camera_board
```

标定板在腕部坐标系中的残差用于评估**所提供样本集的一致性**。这些样本已经参与手眼求解，因此较小的残差不能独立证明相机到基座的变换正确。保留点误差比较 `T_base_camera @ point_camera` 与独立测得的 `point_base`，从而提供单独的精度检查。

报告会显示所提供保留点测量的通过或失败状态。如果误差超标，仍会写入报告文件以便检查失败原因，同时 CLI 以状态码 `1` 退出。即使命令非零退出，也应打开 HTML 检查。查看失败报告时，不要用 `&&` 将报告命令和打开浏览器命令连接起来。

`--samples` 可选；省略后不会显示样本一致性与姿态覆盖诊断。`--validation-points` 也可选，但提供验证点时必须同时指定 `--max-error-m`。没有保留点时，独立验证处于**未验证**状态。可以先检查拟合诊断，随后取得独立测量数据再生成报告。未验证的报告或只含拟合诊断的报告都不能证明标定已通过验收。

左右腕样本集应使用独立结果文件和报告目录。不要混合样本，因为两侧标定板与腕部的安装关系不同。

## 将报告与输入数据一起保留

如需合并内参与手眼检查，在同一条命令中同时传入 `--intrinsics` 与 `--handeye`，并按需提供对应的 `--images`、`--samples` 和验证参数。输出仍使用一个报告目录。将整个目录（包括 `metrics.json` 和 PNG 图）与输入标定文件和测量数据一起保存。每次修订使用不同的输出目录；命令会拒绝非空目录。

检查保留点验证后，使用现有 `apply-calibration` 命令，并传入相同的独立测量数据和阈值。该命令在写入配置前会重新检查验收条件，并保持实机执行关闭。随后完成[部署](deployment.zh-CN.md)，并在[预抓取规划](pregrasp.zh-CN.md)中用 RViz 审核轨迹。标定图不能替代轨迹审核，也不会验证碰撞几何、腕部到 TCP 的安装关系或停止行为。

用于演示报告渲染的合成图像或点必须明确标注为合成数据。合成报告成功只能证明软件流程可运行；实际设备验收需要上述真实测量。
